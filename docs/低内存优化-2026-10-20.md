# 降低基础运行内存：v2.7.7

用户反馈：连续制作的内存增长改善后，运行内存占用仍然偏高，需要继续降低。

## 原因和修改

原首页同时载入了六个游戏预览，即使没有打开对应功能，预览页面及图片也会占用内存。模板中的大量小食材图以 1536 等较大尺寸保存，显示时只有几十到几百像素，PNG 文件虽小，解码后仍按原图宽高占用绘图内存。背景、顾客等分层输出也会加载不需要的厨房素材。

- 只载入当前功能的预览，离开时卸载；返回时从后台状态恢复。控制台未保存的配置仍保留，抽奖模式也会恢复。
- 背景层只载入背景，顾客层不载入整套厨房素材，桌台层不载入背景。刀具、封条等图片只在需要时载入。
- 小食材和器具显示副本最长边使用 512 或 768 像素，控制台缩略图使用 128 像素。宽幅背景、桌台、托盘等保留原尺寸；自定义模板原图、原始资源接口和模板导出保持原内容。
- 显示副本缓存在磁盘，原图变化后重新生成并清理旧副本。串行工作线程处理缩图，空闲后退出，不常驻保存原图或解码缓存；读取或处理失败时回退原图。缩图保留透明边缘和色彩信息，动画 PNG 不缩放。
- 隐藏功能中的界面图片延迟加载，吃吃吃的配置图片也使用缩略图。安装版网页图标使用 128 像素的小图。

沿用 v2.7.6 对制作阶段图片、顾客和台面元素的复用。不添加依赖，不在产品中强制执行垃圾回收。

## 同机内存对照

相同汉堡模板、20 位顾客、一个完整汉堡，使用相同 Electron 测试程序。下面为各页面对应渲染进程的工作集，单位 MiB：

| 场景 | v2.7.6 安装目录 | v2.7.7 安装目录 |
| --- | ---: | ---: |
| 首次打开首页 | 179.06 | 126.73 |
| 打开汉堡控制台 | 463.40 | 209.69 |
| 离开店铺回首页 | 464.78 | 216.08 |
| 首页同时保留独立汉堡画面：控制台 | 464.91 | 216.09 |
| 首页同时保留独立汉堡画面：独立画面 | 347.32 | 173.53 |

首页已载入的预览从 6 个降为 0 个，汉堡控制台只载入 1 个。加载过的首页工作集不会马上回到冷启动水平，Chromium 和系统仍可能保留可回收内存。

以上不是整个应用的总占用。主进程、GPU 和网络进程还有基础开销；进程工作集可能含共享页，不能直接相加当作独占物理内存。缩图首次生成时也有短暂的处理开销，之后直接读取磁盘副本。

## 连续制作验证

五种店铺各连续回放 500 份，共 2500 份，包含制作、出餐、顾客离场和收钱。以下为源码运行时独立店铺渲染进程工作集：

| 店铺 | 第 100 份 | 第 500 份 | 增量 |
| --- | ---: | ---: | ---: |
| 面馆 | 182.80 | 184.86 | 2.06 |
| 汉堡 | 212.96 | 214.91 | 1.95 |
| 香锅 | 211.08 | 211.82 | 0.74 |
| 刀削面 | 199.38 | 200.89 | 1.51 |
| 咖啡 | 192.03 | 204.22 | 12.19 |

DOM 节点数量基本稳定，JavaScript 堆约 1.5–1.6 MiB，没有页面错误或渲染进程崩溃。只有测试程序在采样前回收 JavaScript 临时对象，用于降低测量干扰，产品没有加入强制回收设置。

其他验证：

- `npm test`：256 项通过；新增显示副本尺寸、透明度、缓存并发、源文件更新、线程关闭、错误回退、原图和模板导出一致性测试。
- 五种店铺真实鼠标递餐、排队位置与缩放、保存、取消、输出同步和重启恢复通过。
- 数字炸弹、吃吃吃、礼物推送与制作交叠、模板切换、查封和补货通过。
- 打包版的全部功能预览切换、未保存配置、抽奖模式恢复和分层素材加载通过；打包版礼物画面和渲染进程崩溃恢复通过。

测量及截图：`artifacts/memory-footprint-v2.7.6-final.json`、`artifacts/memory-footprint-v2.7.7-package.json`、`artifacts/shop-memory-v2.7.7.json`、`artifacts/low-memory-v2.7.7-package-console.png`、`artifacts/low-memory-v2.7.7-package-scene.png`。

测试使用离屏 Electron，`--disable-gpu --no-sandbox` 仅用于自动化检查，没有加入产品启动设置。实际数值随系统、窗口数量、礼物头像、模板和硬件变化。尚未在用户实际直播环境长时间复测，也未实际运行安装程序覆盖用户现有安装。小贴图大幅放大时可能比原图略软；原模板和导出仍保留原图。
