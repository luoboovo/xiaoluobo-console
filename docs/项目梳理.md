# 小萝卜游戏控制台 · 项目梳理

> 梳理基线：2026-10-18，工作区当前代码，版本 **v2.5.7**；`npm test` 实测 200 项全部通过（约 15 秒）。
> 本文只描述"现在是什么样、东西在哪、怎么串起来"，不替代 [README](../README.md) 的功能说明。

## 1. 一句话定位

面向 B 站 / 抖音主播的**直播互动控制台 + 小游戏合集**：Electron 桌面程序内嵌一个本地 Node 服务，控制台负责连接直播间、绑定礼物、管理店铺与素材；游戏画面以**普通网页**的形式单独输出，供 OBS / 直播姬当作"浏览器源"采集，不依赖窗口录制。

## 2. 技术栈

| 层 | 选型 |
| --- | --- |
| 桌面壳 | Electron 40.10.6（`desktop.cjs`），单实例锁、无边框透明浮窗、`safeStorage` 加密凭证 |
| 后端 | Node.js ≥22（本机 24.12.0），CommonJS，原生 `http` + `ws`，无框架 |
| 前端 | 原生 ES Module + HTML/CSS，**零构建**（无 Vite/Webpack/TS），页面由服务端按白名单直出 |
| 运行依赖 | `ws` 8.22.0、`qrcode` 1.5.4；Electron 仅为 devDependency |
| 测试 | `node:test`，25 个测试文件 / 200 个用例 |
| 打包 | 自写 `scripts/package.cjs` 复制 Electron 运行时 + Inno Setup 6 生成安装包 |
| 线路 | 本地 HTTP `127.0.0.1:3181`（桌面版）/ `3180`（浏览器开发版） |

## 3. 启动链路

```text
desktop.cjs（Electron 主进程）
├─ safeStorage 读取 credentials.bin（登录凭证）
├─ startServer({ dataDir: %APPDATA%/小萝卜游戏控制台, port: 3181 })
│  ├─ ConsoleServices.init()        账号、礼物库、B站/抖音连接
│  ├─ TemplateLibrary.init()        .luobo 模板库
│  ├─ createPlatformGames × 2       bilibili / douyin，各一套 noodle+overtime+feeding
│  └─ HTTP 路由 + WebSocket /api/events/socket
└─ BrowserWindow.loadURL(http://127.0.0.1:3181)   ← 控制台主窗口
```

- 浏览器开发模式：`npm run dev` → `server.cjs` 独立启动，端口 3180，数据写 `.local-data/`，凭证只存在内存。
- 桌面版与开发版**数据完全隔离**，端口也不同，排查问题时先确认在哪一种模式。

### 前后端同构

`public/noodle/{rules,layout,sign,stir-fry-food,chef}.js` 和 `public/feeding/shared.js` 用 UMD 写法：浏览器挂到 `globalThis`，Node 里直接 `require`。服务端校验布局/规则与前端绘制**用同一份代码**，避免两端规则漂移——这是本项目结构上最关键的一条约定，改规则时必须同时考虑两端。

## 7. 礼物流水线

```text
B站 WS / 抖音 Protobuf
  → services.addEvent('gift')
  → 服务端按序批处理（每批 ≤128 条，手动操作会切断批次）
     ├→ overtime.receiveBatch   倒计时、观众统计、素材待播
     ├→ feeding.receiveBatch    数量、物理、礼物效果
     └→ noodle.receive × N      排队、制作、店铺礼物（偷钱/查封/评分…）
  → 状态广播（普通状态 100ms 合并，动作帧实时）
  → 控制台 / 独立画面 / OBS 网页来源
```

- 每批处理完**原子保存一次**，某条礼物异常不影响后续；批之间 `setImmediate` 让出事件循环。
- 平台数据隔离：B 站用 `dataDir`，抖音用 `dataDir/douyin/`；模板素材共用。
- 平台切换会断开旧直播、暂停旧玩法与倒计时、停掉待播素材。

## 8. 三套玩法与画面输出

| 玩法 | 引擎 | 独立画面 | 交付形式 |
| --- | --- | --- | --- |
| 弹幕面馆（5 种玩法） | `noodle.cjs` + workflow 子模块 | `/noodle/?layer=background\|counter\|customers`，1920×1080 三层 | 内置基础模板 + `.luobo` 按需安装 |
| 巨无霸加班机 | `overtime.cjs` | `/overtime/`（倒计时）、`?media=1`（素材）、`?panel=id`（礼物面板） | 主程序内置 |
| 小萝卜吃吃吃 | `feeding.cjs` + 物理 | `/feeding/?capture=1`，1280×720 透明 | 主程序内置 |

面馆 5 种 workflow：`mix`（臊子面）、`knife-noodles`（刀削面）、`stir-fry`（麻辣香锅）、`jasmine-latte`（咖啡厅）、`burger`（汉堡店）。OBS 层序：顾客 → 桌台 → 主播 → 背景。

## 10. 实时通道与节流

- 浏览器优先 WebSocket（`/api/events/socket`），保留 SSE `/api/events` 兼容；OBS 多来源不会占满 HTTP 连接。
- 频道：`feeding` / `overtime` / `scene`；`motion` 帧绕过 100ms 合并直发。
- 背压：单连接待写 >1 MB 直接断开，重连后拿当前快照，不补历史帧。
- 定时器：物理 30 fps、查封检查 1 s、加班机时钟 1 s、保存 15 s、心跳 15 s、清理 30 s。

## 11. 模板系统

- `.luobo` 是 zip 包：`manifest.json`（`format: xiaoluobo-template`、`schema: 1`、`workflow`、`dish_name`、`cook_seconds`、`sign`、`layout`、`assets`）+ 素材 PNG。
- 安装到用户数据 `templates/`，同时创建一家店铺；同一模板重复安装只保留一张卡。
- 删除模板会连带删除关联店铺，删前写 `noodle.json.before-template-delete-*.json`；磁盘上的 `.luobo` 不受影响。
- 发布包**不包含**任何 `.luobo`，模板按需分发；源工程在 `templates/`，产物在 `artifacts/`。

## 12. 构建与发布

```text
npm install
npm test                 # node --test test/*.test.cjs
npm run dev              # 3180 浏览器开发模式
npm start                # Electron 桌面版（3181）
npm run package          # 生成 release/小萝卜游戏控制台-v{版本}/
```

`scripts/package.cjs` 做的事：复制 Electron 运行时（只留简中/繁中/英文语言包）→ 改名 exe、写入图标 → 复制 `package.json/desktop.cjs/server.cjs/lib/public/data`（排除 `.luobo`、`*.before-paid-*`、旧身体/小手素材）→ 按 1080p 最大缩放压缩 PNG → 复制依赖 `qrcode`/`ws` → 生成 `release/app-version.iss`。

安装包由 Inno Setup 6 编译 `scripts/installer.iss`，输出 `release/installer/`。版本号唯一来源是 `package.json`，界面、便携目录、安装包都读它。

## 13. 质量现状

- `npm test`：**200 / 200 通过**，覆盖面馆各玩法、咖啡厅、汉堡、香锅、加班机、吃吃吃、抖音协议、模板、删除、性能与打包。

- 发布一致性抽查：`release/小萝卜游戏控制台-v2.5.7/resources/app` 中 `app.js`、`server.cjs`、`lib/noodle.cjs`、`public/noodle/game.js` 与源码哈希一致；Electron 版本 40.10.6 对得上。

## 14. 值得注意的问题（按优先级）

1. **没有 Git**。目录里有 `.gitignore`，但 `.git` 不存在；41 个版本目录就是唯一"历史"。任何误删/覆盖都不可恢复。建议立刻 `git init` 并提交首个基线（`release/`、`work/`、`.local-data/`、`.live-verification/` 已在忽略列表）。
2. **约 31.5 GB 构建/验证产物**：`release/` 22 GB（41 个版本目录 + 40 个安装包）、`work/` 8.3 GB、`artifacts/` 0.9 GB、`.live-verification/` 0.3 GB。建议只留 v2.5.7 的便携版与安装包，其余归档到外部盘后删除。
3. **README 是变更日志**：258 行、49 KB，v2.5.x 倒序堆在最前，新用户找不到"当前怎么用"。建议拆成 `README.md`（安装/使用/架构）+ `CHANGELOG.md`（历史版本）。
4. **代码密度高**：大量单行函数与超长语句（如 `public/feeding-console.js`、`lib/feeding.cjs`），审查和合并冲突成本高。热点文件：`public/noodle/game.js`（777 行）、`lib/noodle.cjs`（621 行）、`public/noodle-console.js`（430 行）。新玩法已有 `noodle/workflows` + `stir-fry`/`burger` 的拆分先例，建议延续。
5. **素材重复**：`public/noodle/assets/` 与 `templates/*/assets/` 有大量同名同源 PNG（约 79 MB / 121 MB），打包时两份都进程序。
6. **双端口、双数据目录**容易混淆（3181 桌面 / 3180 开发；`%APPDATA%` / `.local-data`）。
7. **未实现**（README 自述）：程序自动更新、直播伴侣原生场景导入、模型动作映射。
8. **测试盲区**：`desktop.cjs`、浮窗拖拽、OBS/直播姬真实导入只靠 smoke 脚本人工验证。
