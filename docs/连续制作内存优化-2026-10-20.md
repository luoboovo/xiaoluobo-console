# 连续制作内存优化：v2.7.6

用户反馈：汉堡、面馆、香锅等店铺做得越多，内存占用越高。

## 定位与修改

连续重放制作、出餐、顾客离场和收钱后，旧版 JavaScript 堆约 1.5 MiB，DOM 数量也能回落，但渲染进程工作集持续增加。一次 Chromium 内存分配记录中，`cc/image_memory` 图片解码缓存约 251 MiB，属于共享绘图内存，不能只看 JavaScript 堆或进程私有内存判断是否改善。

已修改共用渲染逻辑和制作设备：

- 碗、杯子的各制作阶段保留各自的图片，只切换可见性。咖啡、香锅不再先加载普通面碗再换成自己的图片；汉堡也不再给隐藏的底图加载面馆图片。
- 台面物品按类型复用，顾客按点单图片匹配复用，每类物品及顾客各最多保留 4 个闲置元素。复用时更新编号、姓名、头像名称、点单、选中态、可访问名称、离场状态和定时器；切换模板、关闭预览时清理复用缓存。
- 汉堡食材图层、烤箱和煎台批次复用图片及元素。倒计时更新不会重建整组图片，取出后隐藏，下一批继续使用。
- 咖啡机复用空杯和萃取完成等阶段图片。
- 香锅食材篮只在食材变化时更新，并在当前模板中保留一个精灵图引用，避免每锅清空后重新建立图片解码缓存。

没有修改队伍、出餐、金额、观众统计及存档规则，没有添加依赖，也没有在产品中强制执行垃圾回收。

## 验证

`scripts/smoke-shop-memory.cjs` 通过真实 WebSocket 消息解析器重放状态到 Electron 店铺页面。五种店铺各制作 500 份，共 2500 份；包含成品组装、烤箱/煎台/咖啡机完成、香锅选菜与出锅、递餐、顾客离场及收钱。

测试逐轮检查元素复用、姓名和点单更新、选中态、可访问状态、旧汉堡图层隐藏、制作状态和取餐后隐藏。每 100 份采样一次，**仅在测试中**执行渲染器垃圾回收，以减少未回收 JavaScript 临时对象的干扰。

使用相同原始 PNG 和同一组制作状态，对 v2.7.5 的汉堡与咖啡进行对照。旧版对照不保留测试用的旧 DOM 引用，避免测试脚本替旧版维持图片生命周期，干扰测量。

| 店铺及版本 | 第 100 份工作集 | 第 500 份工作集 | 增量 |
| --- | ---: | ---: | ---: |
| 汉堡 v2.7.5 | 517.21 MiB | 665.55 MiB | 148.34 MiB |
| 汉堡 v2.7.6 | 469.05 MiB | 471.17 MiB | 2.12 MiB |
| 咖啡 v2.7.5 | 370.50 MiB | 665.02 MiB | 294.52 MiB |
| 咖啡 v2.7.6 | 372.54 MiB | 377.88 MiB | 5.34 MiB |

同轮新版面馆工作集从 269.35 到 271.62 MiB，刀削面从 351.77 到 353.34 MiB。五种店铺的采样 DOM 节点数各自保持不变，JavaScript 堆约 1.5–1.6 MiB，无渲染进程崩溃或页面错误。香锅在本轮之后追加了精灵图引用优化并继续进行 1000 份回放验证。

其他验证：

- `npm test`：252 项通过，包含实际制作与金额规则。
- `scripts/smoke-customer-queue.cjs`：五种模板的真实鼠标递餐、队伍移动缩放、保存、取消、输出同步及重启恢复通过。
- `scripts/smoke-gift-rendering.cjs`：制作与收礼推送交叠时固定图片不重复加载，模板切换、查封和补货通过。

测量数据保存于 `artifacts/shop-memory-soak.json`、`artifacts/shop-memory-before-rendered-v2.7.6.json`；香锅追加数据为 `artifacts/shop-memory-stir-1000.json`。

测试使用离屏 Electron 和 `--disable-gpu --no-sandbox` 参数；这些参数仅用于本机自动化测试，没有加入产品设置。工作集包含可回收绘图缓存，会随硬件、窗口数量和系统调度波动，表中数据不是固定节省幅度或总内存上限的承诺。

尚未在用户原直播电脑长时间复测。此次修复针对已复现的图片生命周期及解码缓存增长，不代表已排除所有内存不足的可能。
